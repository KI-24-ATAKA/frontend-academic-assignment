# Задание 7. Адаптивная вёрстка и container queries

В этой работе вы завершите страницу **Frontend Atlas**. HTML, визуальный стиль
компонентов и локальные изображения уже готовы. Ваша задача — построить
mobile-first layout, добавить две перестройки по ширине viewport и сделать
`resource-card` зависимой от ширины собственного контейнера.

Это **одно задание и одна сдача**.

## Что находится в архиве

```text
starter/01-adaptive-atlas/
├── index.html
├── css/
│   ├── base.css          — готовый внешний вид компонентов
│   └── responsive.css    — основной файл вашей работы
└── assets/

reference/                — короткое сравнение @media и @container
preview/                  — результат на трёх контрольных ширинах
```

`base.css` без причины не переписывайте. Основную работу выполняйте в
`responsive.css`.

## Шаг 1. Изучите страницу до написания breakpoints

Откройте HTML и найдите:

- `site-header`;
- `hero`;
- `stats`;
- `learning-layout` с основной областью и sidebar;
- несколько обёрток `resource-slot`;
- повторно используемый блок `resource-card`;
- `principle-grid`;
- footer.

Одна и та же `resource-card` находится:

- в широкой featured-области;
- в сетке из двух карточек;
- в узком sidebar.

Не создавайте отдельные блоки `sidebar-card` и `featured-card`. Различие
контекста должно обрабатываться существующим компонентом.

## Шаг 2. Соберите базовую мобильную версию

Сначала работайте без media queries. Результат должен быть устойчивым примерно
от 320 px.

Настройте:

1. резиновый `.layout-container` с безопасными боковыми отступами;
2. header из двух строк: brand и action сверху, навигация ниже;
3. внутреннюю горизонтальную прокрутку навигации, если ссылкам тесно;
4. одно-колоночный hero;
5. две колонки статистики;
6. одну колонку основной области, карточек и принципов;
7. изображения шириной не больше своего блока;
8. перенос длинных строк без горизонтального скролла страницы;
9. footer в одну колонку.

Базовые правила мобильной версии должны находиться **вне** `@media`.

## Шаг 3. Добавьте первую viewport-перестройку

Когда содержимому хватает места, добавьте первый `@media (min-width: ...)`.
Ориентир — около `48rem`, но breakpoint должен объясняться поведением контента.

После перестройки:

- header помещается в одну строку;
- hero делится на текст и изображение;
- статистика образует четыре колонки;
- обычные материалы образуют две колонки;
- три принципа располагаются в строку;
- footer получает три области.

На этой ширине main и sidebar пока находятся друг под другом.

## Шаг 4. Добавьте desktop-композицию

Добавьте второй `@media (min-width: ...)`. Ориентир — около `70rem`.

На широком экране:

## Шаг 5. Сделайте resource-card контейнерно-зависимой

Каждая карточка уже находится внутри `.resource-slot`.

1. Сделайте `.resource-slot` query container по inline-размеру.
2. Дайте контейнеру имя `resource`.
3. Оставьте базовую карточку вертикальной.
4. При ширине контейнера примерно `32rem` сделайте карточку горизонтальной.
5. При ширине контейнера примерно `48rem` увеличьте свободное пространство и
   размер заголовка широкого варианта.

Используйте:

```css
container-type: inline-size;
container-name: resource;

/* или shorthand */
container: resource / inline-size;

@container resource (min-width: 32rem) {
  /* стили потомков container */
}
```

Важно: `@media` отвечает за крупную композицию страницы, а `@container` — за
внутреннюю композицию карточки.

Проверьте следующий эффект:

- в desktop-layout карточка в sidebar остаётся узкой и вертикальной;
- на tablet-layout тот же sidebar перемещается под main, получает больше места
  и карточка становится горизонтальной;
- featured-карточка становится широкой независимо от карточек в двухколоночной
  сетке.

## Шаг 6. Проверьте промежуточные ширины

Не ограничивайтесь тремя скриншотами.

Проверьте страницу как минимум на:

```text
320, 360, 540, 768, 900, 1120, 1440 px
```

Между ними не должно появляться:

- горизонтального скролла страницы;
- обрезанного текста;
- сжатых изображений;
- наложения header на содержимое;
- слишком узких колонок;
- случайного переключения карточки из-за viewport вместо container.

Для поиска переполнения используйте DevTools. Не маскируйте ошибку правилом
`overflow-x: hidden` у всей страницы.

## Шаг 7. Небольшая самостоятельная часть

Добавьте в конец `.resource-grid` ещё один материал, переиспользовав
`resource-card` и `resource-slot`.

Контент:

```text
Название: Проверка адаптивности без списка устройств
Метка: Практика
Продолжительность: 20 минут
Описание: Меняйте ширину постепенно и фиксируйте момент, когда конкретной
композиции становится тесно.
Теги: DevTools, resize
Изображение: resource-container.svg
```

Используйте обёртку:

```html
<div class="resource-slot resource-slot--featured resource-grid__item">
  <!-- существующий блок resource-card -->
</div>
```

Существующий модификатор `resource-slot--featured` должен растянуть материал на
всю строку сетки. Новые CSS-классы для этой карточки не нужны.

## Ограничения

- Пишите CSS только через плоские БЭМ-классы.
- Не используйте селекторы `.card h3`, `.page > main`, `#route` и подобные.
- Не используйте `!important`.
- Не используйте CSS-фреймворки и JavaScript.
- Не меняйте DOM-порядок содержимого ради другого экрана без необходимости.
- Не задавайте основным колонкам фиксированную ширину в пикселях.
- Не делайте отдельный media query для каждой карточки.
- Не заменяйте container query обычным media query.
- Не скрывайте горизонтальное переполнение у `body` или `.page`.
- Не используйте больше двух viewport breakpoints без обоснования.

## Работа готова, если

- мобильная версия начинается примерно от 320 px и не имеет горизонтального скролла;
- базовые стили написаны mobile-first;
- присутствуют не более двух осмысленных `@media (min-width: ...)`;
- header, hero, статистика, main/sidebar и footer перестраиваются ожидаемо;
- `resource-slot` является query container;
- одна и та же `resource-card` имеет вертикальный и горизонтальный варианты;
- sidebar-карточка зависит от ширины sidebar, а не от viewport;
- используется `clamp()` хотя бы для одного плавного размера;
- длинные строки не ломают Grid и Flexbox;
- добавлена самостоятельная карточка;
- вы можете объяснить отличие `@media` от `@container`.
